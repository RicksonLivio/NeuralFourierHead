# Data sources, licenses and citations

This file lists every dataset used by the code in this repository. For each one it gives the original source, the
license as stated by the source, whether this repository redistributes it, how the file is obtained, and the citation
the source asks for.

All license texts below were read on the source pages on **2026-11-23** (access date for every URL in this file),
unless another date is given. When a page does not state a license, this file says so and makes no claim.
Nothing here is legal advice. If you reuse the data, read the license on the source page yourself.

"Stage 1" and "stage 2" are the two stages of `data/download_data.py`.

- **Stage 1** downloads the four raw files of the main study (`src/v3_*.py`) and checks each one byte for byte against
  the SHA-256 in the table at the end of this file. A mismatch is an error.
- **Stage 2** runs the two processing scripts of the repository, `teste_exemplificacao_nfh/dados/baixar_dados.py` and
  `experimento_backbones_nfh/dados/baixar_dados.py`. They download the other sources and write the processed hourly
  CSV files used by the backbone sweep. The script compares each processed file with the SHA-256 recorded when the
  experiments were run (2026-11-22). A mismatch is a warning, because some sources change over time. The City of
  Melbourne file is not rebuilt: the shipped file is kept and the current API version is saved next to it as
  `*.api_current.csv` for comparison only.

Run `uv run python data/download_data.py [--stage 1|2|all]`. Stage 2 needs the stage 1 files.

Where this file says "processed", the processed file is a derivative of the source. The repository does not
redistribute processed derivatives, except the Melbourne file.

## ETTh1 and ETTh2 (Electricity Transformer Temperature, hourly)

- **Source:** https://github.com/zhouhaoyi/ETDataset (files `ETT-small/ETTh1.csv` and `ETT-small/ETTh2.csv`).
- **License:** the `LICENSE` file of the repository (https://raw.githubusercontent.com/zhouhaoyi/ETDataset/main/LICENSE)
  is "Creative Commons Attribution-NoDerivatives 4.0 International" (CC BY-ND 4.0). Section 2(a)(1) of that
  license grants the right to "A. reproduce and Share the Licensed Material, in whole or in part; and B. produce and
  reproduce, but not Share, Adapted Material." Section 2(a)(5)(B) adds that you may not impose additional terms that
  restrict the license for any recipient.
- **Why this repository does not redistribute them:** the processing script rewrites the file (it moves `OT` to the
  last column and writes ISO 8601 dates, see `teste_exemplificacao_nfh/dados/baixar_dados.py`, function
  `process_etth`). That output can be Adapted Material, which CC BY-ND lets you make and use but not Share. To keep one
  clear rule, the repository ships no ETT file at all, neither raw nor processed. Each user downloads the raw file
  from the source and the script rebuilds the processed file locally.
- **How to get them:** stage 1 downloads `ETTh1.csv` to `data/controle/ETTh1.csv` and `ETTh2.csv` to
  `data/v3_bruto/ETTh2.csv` from
  `https://raw.githubusercontent.com/zhouhaoyi/ETDataset/main/ETT-small/`. Stage 2 writes
  `teste_exemplificacao_nfh/dados/ETTh1.csv` and `ETTh2.csv`.

  work `Informer @ AAAI2021 Best Paper Award`":

## Jena Climate 2009-2016

- **Original data:** weather station of the Max Planck Institute for Biogeochemistry (MPI-BGC), Jena, Germany.
  Station page: https://www.bgc-jena.mpg.de/wetter/. Data download page:
  https://www.bgc-jena.mpg.de/wetter/weather_data.html.
- **File used here:** `jena_climate_2009_2016.csv.zip`, the extract distributed by TensorFlow/Keras at
  https://storage.googleapis.com/tensorflow/tf-keras-datasets/jena_climate_2009_2016.csv.zip. The TensorFlow tutorial
  (https://www.tensorflow.org/tutorials/structured_data/time_series) says the dataset was "recorded by the Max Planck
  Institute for Biogeochemistry" and that the 2009-2016 section "was prepared by François Chollet for his book Deep
  Learning with Python". The Keras example (https://keras.io/examples/timeseries/timeseries_weather_forecasting/) gives
  the location as "Weather Station, Max Planck Institute for Biogeochemistry in Jena, Germany".
- **License:**
  - The MPI-BGC data download page is headed "Nutzungsbedingungen (gemäß Creative Commons CC-BY-4.0)" and "Terms of
    Use (as per Creative Commons CC-BY-4.0)", with a link to https://creativecommons.org/licenses/by/4.0/deed.en.
    Snapshots of the same page in the Internet Archive from 2020-09-30 and 2023-04-01 carry the same heading.
  - The TensorFlow tutorial page says its own content is under CC BY 4.0 and its code samples under Apache 2.0. That
    notice is about the tutorial text and code. It does not state a license for the zip file.
  - What we can say: the MPI-BGC source states CC BY 4.0 for its data. What we cannot say: under which terms the
    2019 TensorFlow copy was made (the file's `last-modified` header is 2019-07-24, earlier than the snapshots we
    could read). If you need certainty, download the data directly from MPI-BGC and ask the contact named on the
    station page.
- **Redistributed here?** No. Stage 1 downloads the zip to `data/v3_bruto/jena_climate_2009_2016.csv.zip`.
- **Processing in stage 2** (`teste_exemplificacao_nfh/dados/baixar_dados.py`, function `process_jena_climate`):
  remove duplicate timestamps, replace the `-9999` wind codes by 0, convert wind speed and direction to the vector
  components `Wx` and `Wy`, average the 10-minute records to hourly values, keep 2009-2011, and keep the columns
  `p_mbar`, `rh_pct`, `Wx`, `Wy`, `T_degC`. The main study (`src/v3_common.py`) applies its own processing to the raw zip.
- **Credit line we use (our wording, not text required by the source):** "Weather station data of the Max Planck
  Institute for Biogeochemistry, Jena (https://www.bgc-jena.mpg.de/wetter/), CC BY 4.0, via the TensorFlow/Keras copy.
  Hourly means, wind vector and year cut made by the authors of this repository."
- **Citation requested by the source:** none found on the station page or on the download page. The
  documentation PDF (https://www.bgc-jena.mpg.de/wetter/Weatherstation.pdf, O. Kolle, 2025-02-04) has no citation
  request either.

## UCI Machine Learning Repository datasets

For all five UCI datasets below, the dataset page shows the same license text, read on 2026-11-23: "This dataset is
licensed under a Creative Commons Attribution 4.0 International (CC BY 4.0) license. This allows for the sharing and
adaptation of the datasets for any purpose, provided that the appropriate credit is given." (link:
https://creativecommons.org/licenses/by/4.0/legalcode). The `license` field of the UCI API record is empty for these
datasets, so the page text is the evidence. The citation below is the one printed under "Citation" on each page.

### Air Quality (id 360)

- **Page:** https://archive.ics.uci.edu/dataset/360/air+quality. DOI 10.24432/C59K5F.
- **Redistributed here?** No. Stage 1 downloads `https://archive.ics.uci.edu/static/public/360/air+quality.zip`
  to `data/v3_bruto/air+quality.zip`.
- **Processing in stage 2** (function `process_air_quality`): treat `-200` as missing, drop columns that are empty or
  have many gaps, drop `PT08.S2(NMHC)`, rename columns; the target is benzene `C6H6`.
- **Citation:** Vito, S. (2008). Air Quality [Dataset]. UCI Machine Learning Repository.
  https://doi.org/10.24432/C59K5F. The UCI record lists as introductory paper: S. De Vito, E. Massera, M. Piga,
  L. Martinotto, G. Francia, "On field calibration of an electronic nose for benzene estimation in an urban
  pollution monitoring scenario", Sensors and Actuators B: Chemical, 2008, doi:10.1016/j.snb.2007.09.060.

### Bike Sharing (id 275)

- **Page:** https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset. DOI 10.24432/C5W894.
- **Redistributed here?** **Yes**, unmodified, because CC BY 4.0 allows it with credit. The files are
  `experimentation/data/bike_sharing/hour.csv` and `Readme_UCI.txt`. They are byte-identical to `hour.csv` and
  `Readme.txt` in the UCI zip (`https://archive.ics.uci.edu/static/public/275/bike+sharing+dataset.zip`); we checked
  the SHA-256 on 2026-11-23 (table at the end). They are used by the `nfh` library tests and tutorial.
- **Stage 2** downloads the zip again and writes the processed `teste_exemplificacao_nfh/dados/bike_sharing_dc.csv`
  (function `process_bike_sharing`: builds the timestamp from `dteday` and `hr` and drops `casual` and `registered`,
  which sum to the target `cnt`). That processed file is not redistributed.
- **Citation:** the UCI page: Fanaee-T, H. (2013). Bike Sharing [Dataset]. UCI Machine Learning Repository.
  https://doi.org/10.24432/C5W894. The dataset's own `Readme_UCI.txt` adds: "Use of this dataset in publications must
  be cited to the following publication: [1] Fanaee-T, Hadi, and Gama, Joao, "Event labeling combining ensemble
  detectors and background knowledge", Progress in Artificial Intelligence (2013): pp. 1-15, Springer Berlin
  Heidelberg, doi:10.1007/s13748-013-0040-3." Cite both.
- **Changes:** none to the shipped files.

## Open Power System Data, time series, version 2020-10-06

- **Source:** https://data.open-power-system-data.org/time_series/2020-10-06/ (DOI
  https://doi.org/10.25832/time_series/2020-10-06). The package contains data published by transmission system
  operators on the ENTSO-E Transparency Platform. We use the file
  `https://data.open-power-system-data.org/time_series/2020-10-06/time_series_60min_singleindex.csv` and three German
  columns: `DE_load_actual_entsoe_transparency`, `DE_wind_generation_actual` and `DE_solar_generation_actual`.
- **License: not stated for the data.** On 2026-11-23 we checked the package page, its `README.md` and its
  `datapackage.json`. The `datapackage.json` has no `licenses` field. The README section "License and attribution"
  contains only an attribution line (below). The only "CC-BY" notice on the package page is "Text is licensed under
  CC-BY license" and refers to the text of the web page. The GitHub repository of the notebook that builds the
  package (https://github.com/Open-Power-System-Data/datapackage_timeseries, tag 2020-10-06) is under the MIT license,
  which covers the code, not the data. We therefore do not claim any license for this data.
- **Primary source:** ENTSO-E states, in its "List of data available for free re-use" (last modified 2023-10-18,
  linked from https://transparencyplatform.zendesk.com/hc/en-us/articles/40921911218961), that the listed items are
  under CC BY 4.0. As we read the five pages of that list, it does not name actual total load or actual generation
  per production type, which are the kinds of series behind our three columns. This is not a statement that the
  columns are unavailable for reuse. It means we found no license text for them, so you must read the ENTSO-E terms
  of use yourself before reusing or redistributing them.
- **Redistributed here?** No. Stage 2 downloads the file and writes
  `experimento_backbones_nfh/dados/opsd_de_solar.csv` (hourly, UTC, 2015-2019, target solar generation in MW,
  covariates load and wind).
- **Attribution requested by the source** (README of the package, Chicago author-date style): "Open Power System
  Data. 2020. Data Package Time series. Version 2020-10-06. https://doi.org/10.25832/time_series/2020-10-06. (Primary
  data from various sources, for a complete list see URL)."
- **Correction (23/11/2026):** `experimento_backbones_nfh/dados/catalogo.json` and `baixar_dados.py` used to label
  this dataset "CC BY 4.0". That label was not supported by the package page and was corrected on 23/11/2026 (protocol
  §10). The label is metadata only: no number of the experiments depends on it.

## City of Melbourne, Pedestrian Counting System (counts per hour)

- **Source:** City of Melbourne Open Data, dataset "Pedestrian Counting System (counts per hour)", publisher
  data.melbourne.vic.gov.au, owner "City of Melbourne Open Data Team". API record:
  https://data.melbourne.vic.gov.au/api/explore/v2.1/catalog/datasets/pedestrian-counting-system-monthly-counts-per-hour
- **License:** the API record gives `license: "CC BY"` and `license_url:
  https://creativecommons.org/licenses/by/4.0/legalcode` (Creative Commons Attribution 4.0 International). The record
  has no `attributions` text and no recommended citation. Section 3(a)(1) of the legal code requires, if you Share the
  material "(including in modified form)": identification of the creator, a copyright notice if supplied, a notice that
  refers to the license, a URI to the material "to the extent reasonably practicable", and "indicate if You modified
  the Licensed Material and retain an indication of any previous modifications", and "indicate the Licensed Material is
  licensed under this Public License, and include the text of, or the URI or hyperlink to, this Public License".
- **Redistributed here?** **Yes**, as a processed file: `experimento_backbones_nfh/dados/melbourne_pedestrian_southbank.csv`.
  We ship it because the public API keeps only about two years of data, so the file used in the experiments cannot
  be downloaded again. SHA-256 is in the table at the end.
- **Modified:** yes. The file is **not** the original dataset. It was produced by `melbourne()` in
  `experimento_backbones_nfh/dados/baixar_dados.py`, with these changes:
  1. Only the sensor with `location_id` = 35 (named `SouthB_T` in `catalogo.json`) was kept.
  2. The timestamp was built as `sensing_date` plus `hourday` hours (local time of Melbourne).
  3. Only 2024-11-22 00:00 to 2026-10-31 23:00 was kept. The file was written on 2026-11-21 (file timestamp), from
     the API data available on that day.
  4. Rows with the same timestamp were averaged (mean of `pedestriancount`).
  5. The series was placed on a complete hourly grid. The result has 17,016 hourly rows. Three hours have no value
     (empty cells) in the file.
  6. Only two columns were written, `date` and `pedestriancount`, with values rounded to six significant digits.
- **Attribution (our wording, proposed because the source gives none):** "Pedestrian Counting System (counts per
  hour), City of Melbourne Open Data, https://data.melbourne.vic.gov.au, licensed under CC BY 4.0
  (https://creativecommons.org/licenses/by/4.0/legalcode). The file in this repository was modified by the authors
  of this repository as listed above (one sensor, fixed window, hourly grid)."
  This notice also applies to every table, figure or result derived from this file.
- **Not covered:** the CC BY 4.0 license of this file does not extend to the code of this repository.

## SINT-M and SINT-U48 (synthetic)

Both are generated by the code in this repository. They contain no third-party data.

- **SINT-M:** multivariate hourly series with four drivers and a target built from two of them with a 48-hour lag.
  Generator: function `gerar` in `src/v3_sintetico_multivariado.py` (seed 2026). Output used by the sweep:
  `experimento_backbones_nfh/dados/SINT-M.csv`, written by `experimento_backbones_nfh/codigo/sinteticos.py`, which
  also checks it against the generator.
- **SINT-U48:** univariate hourly series with a slow trend, a 24-hour and a 12-hour cycle with slowly varying
  amplitude and phase, plus white noise (N = 12000 hours, seed 2026). Generator: `gerar_u48` in
  `experimento_backbones_nfh/codigo/sinteticos.py`. Files: `SINT-U48.csv`, `SINT-U48_com_sinal.csv` (adds the
  noiseless signal) and `sint_u48_oraculo.json` (oracle error and a ridge reference).
- **License:** the license of the code of this repository (`LICENSE`). If you reuse the generated files, cite this
  repository (`CITATION.cff`).
